## Data rules (the app's promise)
- **Florida DBPR is the official base.** The Division of Hotels and Restaurants licenses and inspects every restaurant and publishes the
  files weekly (public records, Ch. 119 F.S.; `playbook/12-sources.md`). Every current seating/non-seating license is a place; Overture
  listings that match one lend it a map point, website and category; unmatched listings are kept only for café-type places and bars (FDACS
  licenses many cafés) when confident (`pipeline/florida.py` keep rule, measured by `pipeline/calibrate.py`).
- **Florida has no grade, and we compute none.** Show DBPR's disposition verbatim, DBPR's own result group for it (Met Inspection Standards /
  Follow-Up Inspection Required / Facility Temporarily Closed) and DBPR's violation counts, with dates. Category 35 is pests *and* outer
  openings: never call it pests. Only the weekly closure file names a pest, in DBPR's words.
- DBPR's inspection search (myfloridalicense.com/portalsearches/VerifyLicensee) is a POST form: link the search page and show the license
  number; never scrape it. FDACS's inspection search is search-only too.
- The App Store build ships **no Google-derived data**. `FL_APP=1` switches `pipeline/florida.py` into that mode and writes `data/app/places.json`
  (statewide core) and `data/app/detail-<region>.json` (inspection history, closures, license, phone, website; read when a place opens).
  Copy all of them to `FloridaEats/Resources/` after every rebuild (unit tests fail if rating/review/price fields appear).
- The Cuban, stone crab, grouper, Keys, oyster, fish camp, Latin and oldest guides list only **hand-checked** places (`hc`, research in
  `data/research/app/*.json` with a 2025–26 source). Seasonal (stone crab season Oct 15 – May 1, summer breaks, hurricane repairs) is not closed.
- Hand-checked places show their verified name (MICHELIN's spelling, then the place's own site, then James Beard's); the listing's name stays
  searchable as `aka`.
- Website links: `pipeline/check_websites.py` (polite, honest UA, resumable). Re-run it before each submission, then rebuild with `FL_APP=1`.
- A place shows a license's inspections only if it is that business. Name matches never count a shared town word ("Miami Subs" is not
  "Wok N Roll Miami") or ignore conflicting food words ("fish" vs "tea"), and name-only geocoding needs the same house number
  (`common.real_share`, `common.kind_conflict`, `geocode.py`). `pipeline/qa_licenses.py` lists any place whose license disagrees on both
  name and house number; fix the cause, or add the place id to its `OK` set with the reason. `pipeline/qa_curated.py` checks that each
  researched place landed on the branch at its researched address (the name-only fallback never takes another branch).
- Places the research finds closed go in `data/research/app/closed_*.json` with a source; they're matched by name, never by address alone
  (a new business often sits at a closed one's address).

## Rebuild
```bash
.venv/bin/python pipeline/fetch_overture.py                       # Overture places, outlines, address points (data/fl)
bash data/raw/dbpr/fetch.sh                                        # DBPR licenses, inspections, closures, fines (weekly)
.venv/bin/python pipeline/convert_xlsx.py                          # yearly inspection workbooks -> parquet (once per new file)
cd pipeline && ../.venv/bin/python dbpr.py && ../.venv/bin/python geocode.py && ../.venv/bin/python listings.py
../.venv/bin/python calibrate.py && ../.venv/bin/python reviews.py   # reviews: web leaderboard only
../.venv/bin/python florida.py && FL_APP=1 ../.venv/bin/python florida.py
../.venv/bin/python qa_licenses.py && ../.venv/bin/python qa_curated.py && cd ..   # own license; hand-checked facts on the right branch
cp data/app/places.json data/app/detail-*.json FloridaEats/Resources/
.venv/bin/python scripts/make-leaderboard.py && .venv/bin/python scripts/make-site.py && .venv/bin/python scripts/qa-site.py
```
The machine is shared and often heavily loaded: run long jobs with `nohup … &` and `python -u`, and never start a second copy of a job.

## Build the app
- The Xcode project is **generated**: `xcodegen generate`. Never commit `FloridaEats.xcodeproj`.
- Simulators (iOS 27.0): **"FL Eats 6.9"** (iPhone 17 Pro Max, `12126C85-C8C2-4EA7-8662-0B0181E88ABF`), **"FL Eats iPad 13"**
  (`E0A6F9BA-D76F-4E52-9070-9D1997F4A883`), **"FL Eats SE"** (`72F1658A-AE42-4A73-8F67-3E5F50ED51B4`) for large-text checks.
  One booted at a time; shut it down when done (`xcrun simctl shutdown <udid>`); check `ps -u $(id -u) | wc -l` (< ~2,300) and that
  fewer than two other "… Eats" simulators are booted before booting. Never touch other sessions' simulators.
- Build/test with the public Xcode and our own DerivedData:
  `DEVELOPER_DIR="/Applications/Xcode 1.app/Contents/Developer" xcodebuild test -project FloridaEats.xcodeproj -scheme FloridaEats -destination 'id=<udid>' -derivedDataPath ./DerivedData CODE_SIGNING_ALLOWED=NO -only-testing:FloridaEatsTests`
  UI smoke test: `-only-testing:FloridaEatsUITests` **without** `CODE_SIGNING_ALLOWED=NO`.
- Screens: `-screenshot <home|cuban|stonecrab|keys|detail|map|honors|oldest|saved|about>` (DEBUG builds only; fixed location downtown Miami).
- **App Store builds come from the public Xcode** (`/Applications/Xcode 1.app`, 27.0); `Xcode.app` is a 27.1 beta. Check `DTXcodeBuild` in the
  archive; bump `CURRENT_PROJECT_VERSION` for every upload.
- `FloridaEats/Resources/PrivacyInfo.xcprivacy`: UserDefaults CA92.1, no tracking, no collected data.
